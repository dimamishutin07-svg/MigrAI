# МИИК — Telegram-бот миграционного консультанта

MVP на Go, PostgreSQL, Docker Compose и RouterAI. Пользователь формирует и подтверждает портрет, после чего может задавать вопросы консультанту.

## Запуск

1. Скопируйте `.env.example` в `.env`, заполните `TELEGRAM_BOT_TOKEN` и `ROUTERAI_API_KEY`.
2. Установите надёжный `POSTGRES_PASSWORD`.
3. `docker compose up --build -d`

Бот использует long polling Telegram. Панель команды включается отдельно через профиль Compose `admin`.

## Панель команды

Панель открывается по HTTPS на домене из `PANEL_DOMAIN`. В `.env` задаются `ADMIN_PASSWORD_SHA256` (SHA-256 случайного пароля длиной от 24 символов) и `ADMIN_SESSION_KEY` (случайный секрет от 32 символов). Пароль выдаётся администратору отдельно. Запуск — `docker compose --profile admin up -d --build bot panel`. Домен должен указывать на сервер, порты 80 и 443 используются для HTTPS.

Панель показывает пользователей, сохранённые портреты, этапы, краткие выдержки, оценки и отзывы. Обновление — каждые 8 секунд. Excel выгружается с учётом поиска и фильтра. История доступна за 90 дней. Почасовая очистка удаляет старые записи истории и контекста сообщений. Портрет и добровольно оставленный контакт сохраняются до `/delete` или `/restart`. Резервные копии обслуживаются отдельно от рабочей базы.

При первом запуске панели прежние сообщения за 90 дней импортируются как краткие выдержки. Имена и ID чатов появляются при следующем обращении пользователя. Для отзыва используется `/feedback`, для добровольного контакта `/contact`.

## Сценарий

- `/start` начинает интервью с короткой анкетой.
- Ответы пользователя извлекаются в структурированный JSON-портрет через RouterAI и сохраняются в PostgreSQL.
- По мере заполнения бот задаёт только недостающие вопросы; затем показывает портрет для подтверждения.
- После подтверждения портрета доступны ответы модели с выдержками из базы знаний. Для правовых утверждений бот указывает адрес официальной страницы и дату её проверки.

## Источники и обновление через чат проекта

Бот загружает `knowledge/sources.json` при старте. В каждой записи указаны страна, заголовок, официальный HTTPS-адрес, дата чтения страницы, темы и краткое содержание по-русски. Вопрос о конкретной стране имеет приоритет над страной в анкете. При свободном выборе бот получает материалы разных направлений. Через 14 дней после проверки бот может дать ссылку для сверки условий, но не использует старую выжимку как подтверждение. PostgreSQL хранит анкеты и историю общения.

Для сбора в чате проекта укажите страну, тему и лимит (по умолчанию 20, максимум 100 документов за запрос). Каталог ссылается на локальные файлы в `knowledge/texts/`. При вопросе бот учитывает последние реплики, подбирает документы и ищет в них подходящие разделы на языке оригинала. У каждого фрагмента есть адрес страницы или приложения и дата проверки. Для ответа доступен текст, который удалось извлечь при сборе.

По каждому запросу:

1. Прочитать официальные страницы, составить краткие выжимки, указать дату фактического чтения. Нечитаемую страницу отметить в отчёте отдельно. Сохранить извлечённый текст страницы и значимые приложения отдельными файлами Markdown. В массиве `texts` карточки для каждого файла указать `title`, `url`, относительный путь `file` и SHA-256 содержимого в `sha256`. Сверить наличие основных разделов, включая последние страницы длинных документов. Обновлять `knowledge/sources.json` по URL, сохраняя другие материалы. В публичный файл помещать только сведения из официальных источников.
2. Проверить каталог командой `docker compose run --rm --no-deps bot check-knowledge` с обновлённым образом, опубликовать файлы на GitHub. В Google-таблице «MigrAI — источники и материалы» обновить список, число источников и ссылку на коммит. Сбор выполняется по запросу в чате.
3. При доступе к VPS доставить именно опубликованную версию в существующий каталог приложения. При первом переходе остановить прежний сервис командой `docker compose stop sourceparser` из каталога со старым Compose-файлом. Сохранить серверный `.env` и существующий том PostgreSQL. Для новой версии выполнить `docker compose up -d --build bot`; при последующих обновлениях материалов достаточно доставить всю папку `knowledge` и выполнить `docker compose restart bot`.
4. Сверить число источников и SHA-256 из `docker compose logs --since 2m bot` (строка `knowledge loaded`) с опубликованным файлом. Убедиться, что после этой строки есть `bot started` и сервис работает. Затем записать результат развёртывания в таблицу. При отсутствии доступа указать «VPS не проверен».

Для диагностики PostgreSQL на сервере используйте `docker compose ps db` и `docker compose exec -T db psql -U migr_ai -d migr_ai -c 'SELECT 1'`. Предыдущий каталог остаётся в базе `migr_ai_knowledge` существующего тома. Состав старой базы можно сверить командой `docker compose exec -T db psql -U migr_ai -d migr_ai_knowledge -c 'SELECT country,count(*) FROM knowledge_documents GROUP BY country ORDER BY country'`. Старые записи, которых нет в файле, следует сверить с оригинальными страницами перед добавлением.

## Ключи и персональные данные

Не помещайте токены в Git. Заданные в переписке Telegram и RouterAI ключи следует отозвать и выпустить заново, так как они раскрыты в чате. Не просите присылать паспорт/сканы в MVP. Профиль содержит чувствительные данные о миграционных обстоятельствах; до публичного запуска нужны политика хранения/удаления, согласие, резервные копии и оценка применимых требований к персональным данным.

## Границы MVP

- Telegram long polling рассчитан на один экземпляр процесса; горизонтальное масштабирование потребует очереди/распределённой блокировки.
- Ответы — информационная навигация, не юридическое заключение и не гарантия визового решения.

## Согласованный продуктовый план

### Аудитория и диалог

- Русскоязычные пользователи с разными гражданствами; рекомендации всегда учитывают паспорт и страну текущего проживания.
- Бот — дружелюбный проводник: задаёт по одному персональному вопросу, принимает свободный ответ и предлагает короткие варианты, когда это удобно.
- Сначала собираются цель, сроки, работа, бюджет, языки и приоритеты; семейная ситуация уточняется по необходимости. Не запрашивать номера паспортов, фото документов и точные даты рождения.
- После интервью бот показывает портрет для проверки и исправления. Приоритеты пользователя определяют сравнение маршрутов; постоянный универсальный рейтинг стран не используется.

### Направления пилота

Рабочий список для первичной проработки источников: Армения, Грузия, Сербия, Казахстан, Турция, Германия, Испания, Вьетнам и Таиланд. Это список направлений, а не утверждение, что каждое подходит любому человеку. Для каждой страны нужны официальные источники и конкретные основания переезда.
